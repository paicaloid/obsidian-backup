# Mission: Algorithms and Data Structures (for working engineers)

## Why
My degree is in Electrical/Electronics and Communications Engineering, not computer science. I learned coding on the job (Python primary), so I have gaps in algorithm and data structure fundamentals. The 2026 performance review named **deeper algorithm / system design** as an improvement area (example: the rate-controlled streamer), and a separate recommendation said to improve coding and algorithm skills. See [[Work History]]. This is the main learning track; [[Designing Data-Intensive Applications]] is the slower side track.

## Success looks like
- Can solve LeetCode-style Easy problems in about 15 min and most Medium problems in about 30-40 min in Python, in the core patterns below.
- Can state time and space complexity of my own code and spot an O(n^2) hiding in a pipeline stage.
- Can explain and re-implement, without looking up: sliding window, token bucket, heap-based top-k, BFS/DFS, union-find, and Hungarian-style assignment (conceptually).
- Can critique the rate-controlled streamer with correct algorithm vocabulary (token bucket vs leaky bucket, queue bounds, drop policy).
- Finished *Learning Algorithms* (Heineman, O'Reilly) and about 100 of the NeetCode 150.

## Constraints
- 3 practice problems a week, plus one book chapter every 1-2 weeks; short sessions alongside real work.
- Python only. Write the solution first, then compare with the best-known one.
- Every pattern gets one note tying it to my codebase (see [[NOTES]]), per [[Preferences]].
- Log each session in `learning-records/` (date, problems, what was hard).

## Out of scope
- Competitive-programming-level topics (advanced DP, segment trees, number theory).
- Interview prep for a specific company; this is for skill and review growth.
- System design (covered by [[Designing Data-Intensive Applications]]).
