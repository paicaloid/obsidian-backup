What DeepSORT Adds to SORT

Four specific additions, each fixing one thing SORTTracker cannot do.

The failure mode, in your own code

SORTTracker.update() does exactly three things every frame: predict where existing tracks moved to (_pre_estimate_kalman_boxes), match those predictions against this frame's detections by Intersection-over-Union (_associate_detections_to_kalman_boxes), and age out anything unmatched for too long (_remove_dead_kalman_boxes, gated by max_age).

That IOU matrix is the entire notion of identity in SORT. A track is "the same object" purely because its predicted box overlaps a new detection's box. There is nothing in KalmanBox or SORTTracker that remembers what an object looks like.

Walk through what happens when a tracked person is occluded for a couple of seconds — behind a pillar, behind another person, out of frame briefly:

  1. No detection matches that Kalman box. It becomes an unmatched_kalman_box every frame.
  2. time_since_update climbs. Once it exceeds max_age (15 frames by default in this codebase — DEFAULT_TRACKER_CONFIG in object_tracker.py), _remove_dead_kalman_boxes deletes it outright.
  3. When the person reappears, there is no old track left to match against. A brand-new KalmanBox is created with a brand-new current_id in _initialize_new_kalman_boxes.

Same physical person, two different track IDs. This is an identity switch, and it is the central failure mode SORT accepts in exchange for being fast and simple.

Why this blocks the lineless counter mission. The current pipeline counts on a line-crossing event — a single instant where identity switches barely matter, because the count only needs the ID to be stable for the one frame it crosses. Lineless counting removes that anchor: correctness now depends on a track ID staying attached to one physical object for its entire visible duration, occlusions included. SORT's IOU-only matching was never designed to guarantee that.

The fix: DeepSORT's four additions

DeepSORT (Wojke, Bewley & Paulus, 2017) keeps SORT's skeleton — Kalman filter, Hungarian assignment — and adds four things on top. Each one targets a specific gap above.

1. An appearance descriptor, so tracks remember what they look like

SORT

A KalmanBox stores only geometry: position, velocity, box size. Nothing visual.

DeepSORT

Each confirmed detection is run through a small CNN, producing a 128-dim appearance vector r. Every track keeps a gallery Rk of its last 100 appearance vectors.

This is the actual fix for the occlusion problem above: when the person reappears, DeepSORT does not need an overlapping box to recognize them — it can compare the new detection's appearance vector against the gallery of every track, including ones that have aged past what SORT would already have deleted.

2. Mahalanobis gating instead of an IOU threshold

SORT

iou_matrix[d_idx, kb_idx] < self.iou_threshold rejects a match. A fixed geometric overlap cutoff, blind to how confident the Kalman filter actually is about its own prediction.

DeepSORT

Uses the Kalman filter's own predicted covariance to compute a Mahalanobis distance between a detection and a track's predicted state, gated at the 95% confidence interval of a chi-squared distribution (threshold ≈ 9.49 for 4 degrees of freedom).

The insight: the Kalman filter already knows how uncertain it is (a track that hasn't been seen in a while has a wider covariance). Mahalanobis gating uses that uncertainty directly, instead of a single flat threshold applied uniformly to every track regardless of how reliable its prediction currently is.

3. A matching cascade instead of one global assignment

SORT

_associate_detections_to_kalman_boxes runs one Hungarian assignment across every track and every detection at once, all treated equally regardless of track age.

DeepSORT

Runs Hungarian assignment once per age bucket, starting with tracks matched most recently (time_since_update = 1) and working outward to tracks not seen in longer. Detections left over after all buckets are matched against unconfirmed / age-1 tracks by IOU, as a fallback.

Why this matters: in one global assignment, a detection that's a mediocre match for a fresh track can still "steal" it away from a better long-lost track — because cost matrices don't know which match is more trustworthy. The cascade fixes this by giving recently-confirmed tracks first pick, on the reasoning that they're the ones the Kalman filter is currently most confident about.

4. A track lifecycle: tentative → confirmed → deleted

SORT

min_hits gates whether a track's box is returned from track_boxes, but every track — hit once or a hundred times — competes equally for matches from frame one.

DeepSORT

A new track starts Tentative and must match for n_init consecutive frames to become Confirmed. A tentative track that misses even once is deleted immediately (no benefit-of-the-doubt); a confirmed track survives up to max_age misses, same as SORT.

This keeps noisy, one-frame-only detections from ever entering the appearance gallery or competing in the matching cascade — they're filtered before they can cause damage, rather than after.
