Tracing the Matching Cascade

One worked frame, by hand — why age order changes the outcome, and what happens to the leftovers.

The setup

One frame. Four tracks already exist, each carrying a time_since_update counter from before this frame's matching runs (see the Kalman primer — this is the same counter that keeps climbing every frame a track goes unmatched).

Tracktime_since_updateState
A1Confirmed
B1Confirmed
C3Confirmed (missed 2 frames — maybe occluded)
D1Tentative (brand new last frame)

Three detections arrive this frame: 1, 2, 3.

Reminder from Lesson 0001: a Tentative track (D) gets no benefit of the doubt. One missed match and it's deleted outright — it doesn't get to accumulate time_since_update like a Confirmed track can.

Same scenario as the table above, animated level by level. Step through with the controls, or hit Play.

Running the cascade

Per Reference 0001's algorithm: loop cascade levels n = 1, 2, 3, …, and at each level, run Hungarian assignment (gated by Mahalanobis + cosine distance) using only the tracks whose time_since_update == n, against whatever detections are still unmatched.

Level n = 1

Tracks with time_since_update == 1: A, B, D. Detections available: 1, 2, 3.

Gated cost matrix comes back favoring A↔1 and B↔2 (both pass Mahalanobis + cosine gates with low cost). D has no detection close enough in appearance to pass gating — say D is a false-positive detection from last frame with nothing similar-looking nearby now.

Result: matched = {A↔1, B↔2}. Unmatched detections remaining: {3}. Unmatched at this level: {D}.

Level n = 2

Tracks with time_since_update == 2: none exist this frame. Level skipped — min_cost_matching is never even called for an empty track set.

Level n = 3

Tracks with time_since_update == 3: C. Detection still unmatched: {3}.

C's Kalman covariance has grown over its 3 missed frames (predict-without-correct, every frame, per the Kalman primer) — wider search area, but detection 3 still falls inside the gate. C↔3 passes.

Result: matched = {C↔3}. No detections left.

Cascade ends

No unmatched detections remain, so the loop exits early (it would otherwise continue up to max_age). Accumulated matches: {A↔1, B↔2, C↔3}. Track D was never matched at any level.

The IOU fallback pass

One thing left: tracks that are Tentative, or that were age-1 and still unmatched, get one more shot — a plain IOU-only match (exactly SORT's rule) against whatever detections are still unmatched after the cascade. Here, there are none. D gets nothing to match against, misses its one allowed frame as a Tentative track, and is deleted.

What the trace shows

Two things a flat, non-cascaded match would not reproduce: (1) A and B — freshly confirmed, tightly gated — got first pick, so an accidental close match between, say, C's stale prediction and detection 1 never had the chance to steal it away. (2) C wasn't abandoned for being old — it still got matched, just after the more-trusted tracks had first pick. Age deprioritizes, it doesn't disqualify.
