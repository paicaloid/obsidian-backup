SORT vs DeepSORT — Glossary & Algorithm

Quick-lookup terms and the matching-cascade algorithm. Kept in sync with the codebase's SORTTracker; update this file, not the lesson, when terminology settles.

Glossary

TermMeaningWhere it lives
TrackOne hypothesized object, carried across frames as an ID + state. SORT: KalmanBox. DeepSORT: Track object with an added appearance gallery.
Kalman filterRecursive motion predictor: predicts next-frame position from current velocity estimate, then corrects using the matched detection. Same role in both — DeepSORT uses a constant-velocity model over (u, v, γ, h, ẋ, ẏ, γ̇, ḣ) (center x/y, aspect ratio, height, and their derivatives).
Hungarian algorithm (linear assignment)Solves the assignment problem: given a cost matrix, find the pairing that minimizes total cost. scipy.optimize.linear_sum_assignment in this codebase.SORT: one global call. DeepSORT: one call per cascade level, plus one IOU-only call for leftovers.
IOU (Intersection-over-Union)Overlap ratio of two boxes: area(A∩B) / area(A∪B). Range [0, 1].SORT: the only matching signal. DeepSORT: still used, but only as the fallback matcher for track age 1 / unconfirmed tracks.
Mahalanobis distanceDistance between a detection and a track's predicted state, scaled by the Kalman filter's own predicted covariance — i.e. "how many standard deviations away, given how uncertain the filter currently is."DeepSORT only. SORT has no motion-uncertainty-aware matching.
GatingRejecting a candidate match outright if its distance exceeds a threshold, before optimization even runs — reduces the cost matrix's search space and blocks obviously-wrong pairings. SORT: IOU threshold gate (iou_threshold, e.g. 0.2–0.3). DeepSORT: Mahalanobis gate (χ² threshold ≈ 9.49 at 95% CI, 4 DOF) and a cosine-distance gate, applied together.
Appearance descriptor (re-ID embedding)A fixed-length vector (128-dim in the original DeepSORT) produced by a small CNN trained for person re-identification — encodes "what this crop looks like," not where it is. Paper's network: 2 conv layers + 6 residual blocks, 128-dim output, L2-normalized onto the unit hypersphere, trained offline on ~1.1M images of 1,261 identities — frozen at inference, never trained on your footage. See Lesson 0003.DeepSORT only. This is the single addition that lets a track survive being deleted-and-recreated across an occlusion.
Cosine distance1 − cos(θ) between two appearance vectors. Small = visually similar.DeepSORT's appearance matching metric, used alongside Mahalanobis distance.
Gallery RkThe last N (100 in the paper) appearance vectors stored per track. Matching compares a new detection against the whole gallery, not just the most recent vector, so a track survives brief pose/lighting changes.DeepSORT only.
Matching cascadeRuns Hungarian assignment separately per "frames since last matched" bucket, most-recent first, instead of one global assignment across all tracks.DeepSORT only — see algorithm below.
Track state: TentativeA brand-new track, not yet trusted. Deleted immediately on its first missed match.DeepSORT only. SORT has no equivalent — every KalmanBox is equally eligible for matching from creation.
Track state: ConfirmedReached after n_init consecutive matched frames. Now tolerates misses up to max_age, same as SORT's aging rule.DeepSORT only.
Track state: DeletedRemoved from the track list — either a tentative track's first miss, or a confirmed track exceeding max_age.Both, though SORT has no tentative-miss shortcut.
n_initConsecutive hits required before Tentative → Confirmed.DeepSORT only — SORT's closest analogue is min_hits, but min_hits only gates whether a box is returned, not whether the track is eligible to keep matching.
max_ageFrames a track may go unmatched before deletion.Same name, same role, in both — SORTTracker.max_age ⟷ DeepSORT's max_age.
hit_streak / time_since_updatePer-track counters: consecutive matched frames, and frames since last matched.Same concept in both; DeepSORT's cascade orders directly by time_since_update.

Algorithm: the matching cascade

From Wojke, Bewley & Paulus (2017), Section 2 / Algorithm 1, restated:

Input: Track indices T = {1, ..., N}, Detection indices D = {1, ..., M},
       max_age

1.  Compute cost matrix C = [c(i,j)] via the combined Mahalanobis + cosine
    gated cost (see below), for all i in T, j in D.
2.  Compute the gate matrix B = [b(i,j)] (1 if the pair passes BOTH the
    Mahalanobis gate and the cosine-distance gate, else 0).
3.  Initialize: matches = {}, unmatched_detections = D

4.  for n = 1 .. max_age:                    # cascade level: age bucket
5.      if unmatched_detections is empty: break
6.      T_n = { i in T : time_since_update(i) == n }
7.      [x_i,j] = min_cost_matching(C, T_n, unmatched_detections)  # Hungarian, gated by B
8.      matches = matches ∪ { (i, j) : x_i,j == 1 }
9.      unmatched_detections = unmatched_detections \ { j : (i,j) in matches }

10. return matches, unmatched_detections, T \ { i : (i,j) in matches }

Leftover unmatched_detections after the cascade are matched against age-1 / unconfirmed tracks in one final IOU-only pass — this is SORT's exact matching rule, kept as-is for the case a track is too new to have a reliable appearance gallery yet.

Gating: Mahalanobis distance

d(1)(i, j) = (d_j − y_i)ᵀ · S_i⁻¹ · (d_j − y_i)

  d_j : detection j's bounding box, in the Kalman state's coordinate space
  y_i : track i's predicted mean state
  S_i : track i's predicted covariance

Gate: accept pair (i, j) only if d(1)(i, j) ≤ t(1),  t(1) = 9.4877
      (χ² 95% confidence interval, 4 degrees of freedom — full state:
      x, y, aspect ratio, height)

      Position-only variant (2 DOF: x, y only) uses t(1) = 5.9915 instead —
      see gate_cost_matrix()'s only_position flag in the reference repo.

Gating: cosine (appearance) distance

d(2)(i, j) = min over r_k in R_i of ( 1 − r_jᵀ r_k )

  R_i : track i's gallery of up to 100 past appearance vectors
  r_j : detection j's appearance vector (from the CNN embedding)

Gate: accept pair (i, j) only if d(2)(i, j) ≤ t(2)
      (t(2) is a tuned hyperparameter, not derived analytically)

Combined cost

c(i, j) = λ · d(1)(i, j) + (1 − λ) · d(2)(i, j)

  Both gates (Mahalanobis AND cosine) must pass for the pair to be
  eligible at all — c(i,j) is only meaningful for pairs that pass both.
  The paper uses λ = 0 in most experiments (appearance dominates),
  since motion is a weak signal under camera motion / occlusion.
